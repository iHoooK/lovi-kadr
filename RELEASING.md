# Выпуск ЛовиКадра

Текущая версия: **0.1.1**, тег релиза: **v0.1.1**.

## Подготовить файлы

Для будущих выпусков увеличивайте `Version`, `AssemblyVersion` и `FileVersion` в `src/PromptixCapture/PromptixCapture.csproj`: например, `0.1.2`, `0.1.2.0`, `0.1.2.0`. Установщик автоматически берёт первые три компонента версии из собранного `LoviKadr.exe`. Тег GitHub должен совпадать: `v0.1.2`. Черновики и предварительные релизы не предлагаются как обновления.

Запустите в Git Bash из корня проекта:

```bash
bash scripts/build-release.sh
```

Скрипт запускает тесты, собирает приложение с .NET, проверяет WPF и создаёт три файла для публикации:

| Файл | Назначение |
| --- | --- |
| `release/LoviKadr-Setup-x64.exe` | Установка и обновление. Имя нельзя менять: его ищет программа. |
| `release/LoviKadr-Portable-x64.zip` | Переносная версия со всеми зависимостями. |
| `release/SHA256SUMS.txt` | SHA-256 обоих файлов для ручной проверки. |

Перед пересборкой скрипт удаляет прежнюю папку `release`; сохраните нужные старые выпуски отдельно.

## Опубликовать на GitHub

1. Сохраните изменения кода в Git и отправьте их в `iHoooK/lovi-kadr`. Выпуск должен соответствовать тому коммиту, из которого собраны файлы.
2. Откройте [создание релиза](https://github.com/iHoooK/lovi-kadr/releases/new).
3. Выберите или создайте тег **v0.1.1** на коммите этого выпуска. Заголовок: **ЛовиКадр 0.1.1**.
4. Вставьте описание из [RELEASE_NOTES.md](RELEASE_NOTES.md).
5. В область вложений релиза загрузите **все три файла** из таблицы. Не загружайте их в исходники репозитория и не используйте автоматически созданный GitHub `Source code (zip)` вместо готовой portable-версии.
6. Дождитесь завершения загрузки. Оставьте **Set as a pre-release** выключенным, выберите **Set as the latest release**, если этот пункт доступен, и нажмите **Publish release**.

Репозиторий и релиз должны быть публичными. Приложение использует `GET https://api.github.com/repos/iHoooK/lovi-kadr/releases/latest` без авторизации. При приватном репозитории первая проверка сообщит, что релиз недоступен; секретные токены в клиент добавлять не нужно.

GitHub автоматически рассчитывает поле `digest` для загруженного установщика. Программа принимает только SHA-256, правильный размер и адрес файла внутри этого репозитория. Если установщик отсутствует или GitHub не вернул корректный `digest`, программа покажет новую версию со ссылкой на релиз и не будет запускать файл автоматически. `SHA256SUMS.txt` нужен для ручной проверки; обновлятор использует именно метаданные GitHub. Контрольная сумма проверяет целостность файла, а доверие к выпуску опирается на HTTPS и доступ к аккаунту GitHub; это не цифровая подпись издателя Windows.

## Проверить опубликованный выпуск

- На версии 0.1.1 после публикации v0.1.1 проверка должна сообщить, что версия актуальна.
- Пользователям 0.1.0 отправьте ссылку на установщик v0.1.1: первая установка обновления выполняется вручную. Удалять текущую установленную версию не нужно, если она уже находится в `Program Files`; для старой установки в `%LocalAppData%\Programs\LoviKadr` используйте инструкцию из README.
- Для полного сценария обновления оставьте установленную 0.1.1 и в следующий раз опубликуйте собранную 0.1.2 как v0.1.2. На 0.1.1 нажмите **Настройки → О программе → Проверить обновления → Скачать и установить…**. После установки проверьте номер версии и сохранённые настройки.

Официальная документация: [создание релизов](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository), [API последнего релиза и поля файлов](https://docs.github.com/en/rest/releases/releases#get-the-latest-release).
